## What is in here

The repository contains:
- **Protocol v2** (`code/scripts/uase_v2.py`): a leakage-free evaluation of 14 detector channels. It uses:
  - train-only scaling;
  - fixed hyper-parameters;
  - out-of-fold threshold calibration;
  - a nested development split inside each training prefix.
- **UASE-v2 meta layer** (`code/scripts/uase_meta.py`): picks the fusion rule (a single channel, a per-series rule, or an equal-weight ECDF rank fusion of the top-k channels) once per corpus, using development data only. It also evaluates that choice on the test splits and cross-validates the selection step itself.
- **Statistics:**
  - `v2_stats.py` and `run_stats.sh`: Friedman/Nemenyi tests, Holm-corrected Wilcoxon tests and bootstrap CIs.
  - `v2_k8s_stats.py`: moving-block bootstrap and McNemar tests for Kubernetes.
- **Paper tables and figures:** `make_v2_tables.py`, `make_v2_figures.py` and `make_latency_table.py` write to `paper/tables/` and `paper/files/images/v2/`.
- **Latency benchmark** (`measure_latency.py`): per-point streaming latency, throughput and fit time.
- **Kubernetes corpus** (`code/data/k8s_metrics.csv`), generated by our `generate_k8s_metrics.py`. Locust load profile and manifest: `locustfile.py`, `code/k8s/deployment.yaml`. Optional Prometheus collector: `collect_prometheus_metrics.py`.
- **All v2 result files** in `code/data/v2/`: per-series metrics, meta-layer selections, statistics and latency logs. Every number in the paper is generated from these files.
- **Published v1 results** (`code/data/yahoo_s5_overall.csv`, `cloud_monitoring_overall.csv`, `ml_comparison_results.csv`) and **v1 reproduction results** (`code/data/v1_repro_*`), used in the paper's audit and the v1-vs-v2 figure.

The per-series channel scores (`code/data/v2/scores/`, ~106 MB) are not committed. Regenerate them with `--save-scores`.

### Getting Yahoo S5

1. Request the dataset *"ydata-labeled-time-series-anomalies-v1_0"* (S5 - A Labeled Anomaly Detection Dataset, version 1.0). Use either route:
   - Yahoo Webscope: https://webscope.sandbox.yahoo.com/catalog.php?datatype=s&did=70
   - The gated Hugging Face copy, after logging in and accepting the Yahoo Dataset Terms of Use: https://huggingface.co/datasets/YahooResearch/ydata-labeled-time-series-anomalies-v1_0
2. Unpack it so that these folders exist:
   ```
   code/data/yahoo_s5/A1Benchmark/real_*.csv
   code/data/yahoo_s5/A2Benchmark/synthetic_*.csv
   code/data/yahoo_s5/A3Benchmark/A3Benchmark-TS*.csv
   ```

   `code/data/yahoo_s5/` is in `.gitignore`. Never commit it.
3. Publications using it should acknowledge: *Yahoo! Webscope dataset ydata-labeled-time-series-anomalies-v1_0 [http://research.yahoo.com/Academic_Relations]*.

## Reproducing the paper

Run all commands from the repository root. Run times are for an 8-vCPU machine.

```bash
cd code
# 1) Detector channels, development and test splits (add --save-scores; the meta layer needs the scores)
for MODE in dev test; do
  python scripts/uase_v2.py --dataset yahoo --mode $MODE --jobs 3 --save-scores
  python scripts/uase_v2.py --dataset cloud --mode $MODE --jobs 3 --save-scores
  python scripts/uase_v2.py --dataset k8s   --mode $MODE --norm A --save-scores
  python scripts/uase_v2.py --dataset k8s   --mode $MODE --norm D --save-scores
done
# 2) UASE-v2 meta layer: select on dev, then evaluate on test (writes code/data/v2/meta/)
python scripts/uase_meta.py --dataset yahoo --evaluate-test
python scripts/uase_meta.py --dataset cloud --evaluate-test
python scripts/uase_meta.py --dataset k8s --bench k8s_A --evaluate-test
python scripts/uase_meta.py --dataset k8s --bench k8s_D --evaluate-test
#    optional: same, plus a 5-fold cross-validated estimate of the selection step (slow, ~1.5 h for Yahoo)
python scripts/uase_meta.py --dataset yahoo --evaluate-test --cv
python scripts/uase_meta.py --dataset cloud --evaluate-test --cv
# 3) Statistics (code/data/v2/stats/)
bash scripts/run_stats.sh yahoo noresid
bash scripts/run_stats.sh cloud
python scripts/v2_k8s_stats.py A
python scripts/v2_k8s_stats.py D
# 4) Tables and figures for the paper (paper/tables, paper/files/images/v2, code/figures/v2)
python scripts/make_v2_tables.py
python scripts/make_v2_figures.py
# 5) Latency benchmark (code/data/v2/latency/) and its tables
python scripts/measure_latency.py
python scripts/make_latency_table.py
```

| Paper item | Produced by | Source files |
|---|---|---|
| Kubernetes tables (A, D), McNemar/bootstrap | `uase_meta.py`, `v2_k8s_stats.py`, `make_v2_tables.py` | `data/v2/meta/k8s_k8s_*`, `data/v2/stats/k8s_*_bootstrap.csv` |
| Yahoo / Cloud tables, CD diagrams | `uase_meta.py`, `run_stats.sh`, `make_v2_tables.py`, `make_v2_figures.py` | `data/v2/meta/{yahoo,cloud}_*`, `data/v2/stats/*` |
| Meta-layer ablation | `uase_meta.py` | `data/v2/meta/*_dev_config_means.csv` |
| Latency and fit-time tables | `measure_latency.py`, `make_latency_table.py` | `data/v2/latency/*` |

Steps 4-5 need only the committed result files, so the tables and figures can be rebuilt without Yahoo S5. Steps 1-3 for Yahoo require the dataset (see above).

## Notes and limitations

- The latency benchmark replays recorded test points on one CPU thread. It does not include a live Prometheus stack. The univariate feature update recomputes the full history, so its cost grows with history length (see the paper).
- The Spectral Residual channel is computed transductively on the unlabelled series in the accuracy runs. It is computed causally in the latency benchmark.
- `download_yahoo_s5.py` only checks that the data are present. It deliberately does not download from third-party mirrors.
